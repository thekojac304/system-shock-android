ARCHITECTURE AND CHANGED FUNCTIONS

ExternalMusic.c/.h extend AUDIO1's existing playback owner. ExternalMusicPack
contains a name and a small ExternalMusicEntry table (level, path).
ExternalMusicMode/ModeName/Path handle mode validation and lookup without SDL.
ExternalMusicUpdate handles selection, one decoder, deck departure, fallback,
volume and resume. Original has no entries and makes no mixer calls unless
it is releasing a previously active replacement. Unknown modes are Original.

The current visit is identified by mode and actual player level. Changing
either releases the previous decoder and resets the failure latch. Repeated
updates on that visit never reopen or restart a track. A Grove-to-Grove visit
starts the shared groves.mp3 once for the new level. This intentionally treats
each Grove as a deck visit, even though all three use the same filename.

Prefs.c: SetDefaultPrefs, LoadPrefs, SavePrefs, trim.
Prefs.h: soSoundtrack supersedes soReplacementMedicalMusic; not savegame data.
musicai.c: mlimbs_do_ai supplies the generic mode, actual level, gameplay
eligibility and current music volume. Normal movement, load_game and QA1 all
reach this same update. QA1 still calls trap_teleport_func; no QA-only music
path or new transition hooks were added.

Existing Xmi.c hooks are reused unchanged: StopTheMusic suspends replacement
playback, StartTrack suppresses simultaneous stock MIDI, UpdateVolumeXMI
forwards volume/ducking. No device, postmix, SFX channel or Java lifecycle
changes were needed. The existing CMake source lists already include the module.

Tests updated: tests/audio/external_music_test.c and external_music_smoke.c.
New helpers: scripts/install-qa-soundtrack.py and scripts/test-audio2.py.
The existing scripts/test-audio1.ps1 now runs the expanded playback regression
source, retaining its AUDIO1 lifecycle cases and no-mixer build coverage.

PREFERENCE AND MIGRATION

In the existing app-private files/prefs.txt, use exactly one of:
  soundtrack = original
  soundtrack = remake

Names are case-insensitive. Missing/empty/invalid values resolve to Original.
Temporary compatibility: when no soundtrack key exists,
replacement_medical_music = true (also yes or 1) selects the Remake pack.
An explicit soundtrack key ALWAYS wins, including an invalid value, regardless
of line order. Last duplicate soundtrack key wins, matching the parser style.
SavePrefs writes the generic key and no longer writes the legacy boolean.
Unrelated recognized preferences retain the existing load/save behavior.
As before, the game's SavePrefs rewrites its known keys, not comments or
unknown keys. The host helper preserves unrelated lines and comments.

Use UTF-8 WITHOUT BOM, never UTF-16. The byte-oriented game parser remains
unchanged in this respect. SavePrefs writes plain ASCII-compatible UTF-8.
The installer reads UTF-8 strictly, strips a UTF-8 BOM if present, preserves
unrelated UTF-8 text, and refuses UTF-16 rather than damaging it. trim now
handles an empty value safely and passes unsigned bytes to ctype functions.

Selection is CONFIG-BASED in AUDIO2; restart the app after editing prefs.
UI selection is deferred. The legacy sound options use resource-backed
labels/states and constrained button slots; touch settings would require a
new preference/event/layout path. Existing touch layouts were left intact.

SPECIAL CASES AND LIFECYCLE

Stock: title/menu (titloop), intro/movie audio, endgame/credits (endloop or
the stock credits theme), death transitions, cyberspace, all unmapped levels.
They use existing non-gameplay/stop hooks or the cyber flag and have no pack
entries. GAME_LOOP, FULLSCREEN_LOOP and AUTOMAP_LOOP can activate replacements
only while music is enabled and the player is alive and outside cyberspace.

Elevators are NOT separately mapped. Under Remake, a working current-deck
track also covers its elevator/music zones, preserving AUDIO1's treatment.
The destination level selects its track on the first eligible update even
when the engine retains the elevator's stock theme. Stock theme loading and
transition requests remain intact for fallback and special contexts.

In-game pause retains the stock policy of continuing music. SDL Android
background/foreground pauses/resumes the existing mixer device; AUDIO2 adds
no second player or Java callback. StopTheMusic suspends the decoder and
restores the synth hook for menus/death/theme reloads. Returning to eligible
same-deck gameplay resumes that retained decoder instead of restarting it.
Departure/mode change/shutdown frees it. A loaded same-deck save may resume
the retained track; a new process starts at the beginning. No music position
is written to game saves.

FALLBACK AND LOGGING

Missing, unreadable, decoder-load, unsupported-format, playback-start and
unexpected-stream-stop failures return control to stock sequencing and
restore the synth hook and its normal gain. No file is required for other
decks to work. Failures are latched for that deck visit to avoid retry/log
spam; leave and return, change mode, or restart after fixing a file.
Music must be enabled and its volume above zero to hear either soundtrack.

Only MP3 streams are accepted. Renaming WAV/OGG to .mp3 is not conversion.
SDL_mixer supplies the error text; it can be imprecise (the tested garbage
file returned "Out of memory"). The fallback still logged its deck/path and
worked. This is graceful handling of reported decoder failures, not a claim
that arbitrary native-decoder defects or invalid game data cannot crash.

Consistent message prefix: ExternalMusic
Events: mode, mapping, switch, start, suspend, resume, stop, fallback.
No ordinary frame/update logs; repeated updates/failures are quiet.
Missing-file diagnostics include SDL's "Couldn't open" and the exact path.
SDL_Log appears under Android tag SDL/APP on the tested hardware, NOT just SDL.
PowerShell/cmd filter:
  adb logcat -v threadtime "SDL/APP:I" "SDL:I" "AndroidRuntime:E" "*:S"
Or capture all output and search for ExternalMusic / QA1 teleport.

INSTALL A USER-OWNED PACK

From C:\Dev\system-shock-android, with Python 3.9+ and an authorized QA device:
  python scripts/install-qa-soundtrack.py "C:\MyMusic\Remake" --soundtrack remake
Select Original without changing any installed tracks:
  python scripts/install-qa-soundtrack.py --soundtrack original
Optional: --serial DEVICE_SERIAL --adb "C:\path\to\adb.exe"

Save your session and stop the QA app before running the helper. It refuses
to interrupt a running app. Launch QA once beforehand to create prefs.txt.
The helper recognizes only the eleven filenames above (source casing is
normalized), rejects empty/ambiguous files, and leaves unprovided/unrelated
files alone. It verifies staged and final sizes before reporting filenames.
It copies to a temporary private filename and renames after verification.
Preferences are also verified byte-for-byte and backed up under
dist/audio2/preferences/. It does not reset data or download anything.

Binary safety: adb push uses the sync protocol through a uniquely named
/data/local/tmp/systemshock-audio2-* staging file, then run-as copies it into
private storage; the shell staging file is removed in finally. Raw exec-out
reads prevent CR/LF alteration. On this Windows ADB build both redirected
file stdin AND a subprocess pipe truncated MP3 at byte 0x1a. Do not reuse
AUDIO1's historical binary-stdin instructions on this build.

LIMITS AND NEXT MILESTONES

Full MP3 looping only (-1): official OST tracks may have authored endings,
so their restart is not seamless. No loop points, intro+loop segments,
crossfades, gapless edits or layered tracks were implemented. Missing files
are retried on a new visit, not polled live. MP3 opening/indexing latency
depends on supplied files. Existing audio-lifecycle investigation is not
claimed fixed. Hardware listening and a complete long-session pass remain.

AUDIO3 can add exploration/combat variants or loop metadata to pack entries
without rewriting deck lookup/preferences/lifecycle ownership. The existing
WALKING_SCORE/PERIL_SCORE/COMBAT_SCORE and combat/peril hooks are future inputs;
stock sequencing is skipped during replacement playback, so AUDIO3 must
explicitly maintain/consume intensity signals. An SS2/Custom pack can add a
registry entry and mapping table; neither is exposed by AUDIO2. True crossfade
or dual-layer playback will require a deliberate multi-stream mixer backend:
SDL_mixer's single music slot cannot supply that just by adding metadata.
