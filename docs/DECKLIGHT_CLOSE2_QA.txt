Maintenance — exact fallback and decision
-----------------------------------------
Reproduction: QA teleport to Maintenance, level 3, tile (34,39), camera about
(34.5,39.5). Repeated whole-view fallback: "GPU1B whole-view SOFTWARE
reason=unsupported object representation", first count 1 and then recurring.
At GpuWorld.c:749 gpu_world_object rejects object 77 because its triple is
INVISO_CRIT_TRIPLE (0x0e0007). The logged object is class 14 (critter),
subclass 0, type 7, representation FAUBJ_CRIT=4, animation frame 1, located
at (31.5,27.5,0.34375). The level archive gives spec ID 5 and HP 396;
object properties specify render_type 4, flags 198. The rejection occurs before
the common GPU sprite command is accepted, then GpuWorld.c:340 records the
whole-view software reason. No weaker partial fallback was introduced.

Its material is the posture/view/frame-selected critter bitmap Ref returned by
get_critter_bitmap_obj_fast and ref_from_critter_data, not a static wall or
object texture. The active frame is 1. The software path in gameobj.c decodes
the RSD8 bitmap through gr_rsd8_convert, marks it BMT_TLUC8 under
TRANSLUCENT_INVISOS, and calls _fr_draw_bitmap. This build does not define
TLUC_IN_2D, so it takes that conversion branch. Indexed translucency depends
on pixels already in the destination. This is D (destination-dependent
translucency) and needs F (ordering/compositing architecture) to preserve the
original appearance. An ordinary alpha sprite would be an incorrect mapping.
Per the stop rule, no renderer support or Maintenance promotion was attempted.
The diagnostic-only logging edit was removed; GpuWorld.c is unchanged. Its
previous 283-light, 1,845-surface candidate still loads (previous measured
7.326 ms), but that fact cannot override the sampled room's fallback.
Maintenance remains POST-ONLY. Existing complete software fallback is intact;
no stale or partially rendered GPU world was accepted in the failing view.

Engineering — slot root cause and bounded fix
---------------------------------------------
Original level resource base 4700, tile resource 4705: tile 2109 at (61,32),
raw 16-byte record 070c04044202360300850000ff000000. It is terrain type 7,
a basic slope. Packed texture word 0x0336 stores wall slot 54, floor slot 0,
ceiling slot 12. The map texture table resource 4707 has only 54 entries,
indexed 0..53; there is no stored value or bitmap for slot 54. The loader
previously treated every stored slot as a drawable texture and stopped with
"Unresolved texture slot". This is a genuinely unused wall entry, not an
alias, animation reference, sentinel with art, or missing object texture.
The tile's MAP_FRIEND_FULL_MASK bit is set (flags byte 0x85). The original
wall parser uses each neighbor's wall slot for external walls under that flag;
the type-7 basic slope has no internal wall. Neighbor walls have different
textures, so fabricating one alias would be wrong.

scripts/horror_author.py now represents this one provably unused class as an
absent wall texture: only an out-of-range WALL slot on a friend-material basic
slope (terrain 6..17) is allowed to become null. Other missing slots still
fail. Source generation already ignores an absent material. No map bytes,
texture table, art, runtime wall path, receiver geometry, SurfaceId, clipping,
portal inference or bounds changed. A focused synthetic test accepts this
record and rejects the same slot on a non-friend slope or a different terrain
class. The original level inventory now completes deterministically.

Read-only pre-rule inventory found 203 candidates and 50 accepted sources:
35=20, 36=19, 185=11. Engineering also repeats raw fixture families 155
(487 candidates) and 188 (136); bright 9 and 102 are excluded non-emissive
families. Visual review of owned texture 155 showed a small white bulb inside
a dark brown housing. Its emissive palette-index mask [176,177,178,179,180]
selects 204 of 16,384 pixels and excludes the housing. Existing reviewed
188 mask is reused with a deck-only Engineering classification. Source IDs
35/36/185 retain their prior classification; screens and industrial walls
remain review-only, without broad new source heuristics.

The reviewed Engineering material rules add fixture 155 (warm RGB
[1.0,0.74,0.48]) and reuse 188 ([0.82,0.88,0.94]); one
engineering_industrial archetype uses cool, low ambient [0.84,0.9,0.96]
at 0.16 intensity. Generated sources use existing ceiling/object intensity,
radius and per-receiver bounds. No coordinates or rooms were authored. Fog is
disabled in the generated profile; Post Auto supplies global mood. Post FX
remains FULL (mode 3). The final source profile has 826 candidates and 350
