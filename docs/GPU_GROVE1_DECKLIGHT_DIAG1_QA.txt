2. GROVE SOURCE PATH AND CHANGE
The terrain ceiling path uses textprop force_dir and the original star special
renderer. star_poly draws the open-sky polygon as indexed 255 (reserved black)
and star_empty accumulates its clipped depth/radius. fr_pipe_go_3 renders
terrain and objects into the indexed software world. star_render then rotates
the original std_vec/std_col catalogue by game time, projects with
star_transform_point, and writes a star pixel only when gr_get_pixel at that
position is still 0xff. Larger/anti-aliased stars use that same pixel test.
The test is the original exact open-sky coverage and already excludes solid
ceiling, lattice struts, walls, objects, and terrain in painter order. The
source sky polygon also enters the existing GPU polygon capture; textured sky
uses the existing texture path. There is no replacement skybox or background.

The change removes only the unconditional sky/stars whole-view reject in
star_empty. fr_render_stars now runs after the indexed world is complete and
before gpu_world_end submits it; fr_send_view still handles the subsequent
indexed UI/copy. Each software-approved star pixel is copied into a bounded
16,384-point GPU command array with its original palette index. A 1-pixel
GLES point pass runs after ordinary world draws on the world target, before
world-only Post. The point shader fetches the existing palette; it does not
invent positions, colors, star counts, lighting, or sky coverage. A pixel
outside the view, star command overflow, shader/link/GL failure or another
unsupported draw still fails closed to the original whole-view software path.
The existing software world remains the exact coverage oracle; no GPU readback
or new stencil approximation was introduced. The sky and point pass are world
content, so HUD, weapon, and touch composition remain outside the post pass.
