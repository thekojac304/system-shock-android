3. GLES / SDL INTEGRATION

One Android Surface, one SDL window and SDL-managed ES context. No second Java
surface/context or framework. SDL's GLES2 renderer runs in the requested ES3
context. Window/presenter failure retries an ES2 software-world presenter; backend
capability checks then reject GPU mode. Real low-capability startup was not tested
on this ES3.2 phone; private ES3-unavailable injection tests backend rejection.

Hardware logs: EGL 1.5 Android META-EGL; OpenGL ES 3.2 V@0842.19.13;
GLSL OpenGL ES GLSL ES 3.20; vendor Qualcomm; renderer Adreno (TM) 840.
GLSL source is #version 300 es. Vertex and fragment compile=1, program link=1.
FBO completeness = 0x8cd5, GL error=0; color attachment queried as 8/8/8/8;
depth/stencil allocation GL_DEPTH24_STENCIL8. These are logged on reconstruction.

The coarse pass bridge flushes SDL before native commands and saves/restores
program, VAO, array buffer, active texture unit, units 0/1 texture bindings,
draw/read FBOs, renderbuffer, viewport/scissor, unpack alignment/row length/skips,
pixel-unpack buffer, blend/depth/stencil/scissor/cull enables, color/depth write
masks and clear color. Attribute pointers and EBO are isolated in a private VAO.
Blend equations/functions, stencil functions and sampler objects are not changed.
No glGet per polygon, MakeCurrent per draw, glFinish, or runtime pixel readback.

9. INDEXED ART / PALETTE / TRANSPARENCY

Original FLAT8 pixels or owned decoded RSD8 pixels upload to GL_R8UI. A separate
256x1 GL_RGBA8 palette receives canonical SetSDLPalette data before display gamma.
Integer texelFetch samples the nearest index; indices are never interpolated.
UV repeat is explicit with fract. Cutout discard(index==0) happens ONLY when the
source bitmap has BMF_TRANS. Index zero remains opaque otherwise. TLUC8 and other
destination-dependent effects reject the whole view instead of approximating.

Palette-generation changes upload 1024 palette bytes, not static index textures.
During final GPU timing the palette generation advanced 5602 -> 6202 -> 6802,
while static texture uploads/bytes stayed zero. Paused retained commands also
replay when the palette changes. This exercises the game's continuing palette
updates; it is not a complete audit of every animated/cycling resource family.

10. CACHE / LIFETIME

Identity is content hash (64-bit FNV-style), dimensions and byte-for-byte equality;
hash collisions cannot alias different pixels. No pointer-address identity.
CPU content is owned across resource unlocks, temporary monitor/model sources,
decoded RSD scratch reuse and GL recreation. Current animated content produces a
different cache entry. Static matching art is shared. GL names are derived state.

Limits: 512 textures, each at most 1024x1024; 4096 commands; 32768 vertices.
No eviction yet: sustained novel dynamic images eventually cause explicit
software fallback. This intentionally bounded Medical cache is not a general
animation-streaming system. Buffers/metadata are retained for the process lifetime.

11. LIGHTING / GAMMA

CPU records feed uniforms; Medical constants are not baked into the shader.
For canonical palette RGB P normalized to [0,1], scalar darkness D in [0,16]:
  base = pow(P, 2.2)
  scalar = pow(clamp(1 - D/16, 0, 1), 2)
  illumination = ambientRGB * scalar
               + SUM(receivingLightRGB * intensity * max(0,1-distance/radius)^2)
  linear = base * illumination
  emissive or original invariant index: linear = base
  output = pow(clamp(linear,0,1), displayExponent/2.2)
  g = clamp(prefs.gamma/100, .1, 1)
  displayExponent = 1 / ((1 - (1-g)^2) * 2.2)

This uses a simple power-law approximation, not a calibrated sRGB transfer.
Gamma is encoded once in GPU output, with the existing display setting. Original
scalar rows are baseline data only; local RGB contributions never go through
SHADTABL. RGBA8 still has finite output precision and source art is still indexed.
No normals, PBR, specular, replacement art, smoothing, bloom, AO or shadows.
