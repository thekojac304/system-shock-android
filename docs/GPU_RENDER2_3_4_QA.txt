13. KNOWN RENDERER FALLBACKS / FAILURE HANDLING

Whole-view software is selected for the excluded views/classes above; unsupported
bitmap format/translucency/dimensions, custom CLUT, unsupported primitive/count,
non-convex topology, nonpositive clipped depth, singular camera, current command/
texture working set over budget, allocation failure, initialization/shader/FBO
failure, failed native submission, and failed GPU composition.

Software traversal/rasterization is still performed during capture. A rejected
GPU view therefore retains complete software geometry/objects, not a hybrid
object patchwork. Software world is discarded only after successful submission.

Safety fixes in this campaign:
- Sequential sensaround formerly invalidated the already-cleared primary view.
  Primary preflight now forces the entire frame to software while it is active;
  secondary/picking calls separately preserve primary command ownership.
- Convexity now checks all boundary half-planes, not only consecutive turns.
- Any detected submission/upload GL error discards all derived resources and
  selects Original until an explicit renderer retry. An allocated GL name or
  advanced palette generation can no longer mask a failed image/VBO upload.
- gpu_world_compose checks SDL_RenderCopy. On failure, restore_software_world
  fills the saved world under the existing UI sentinel and selects Original.
- A replaced EGL context now invalidates GPU metadata and transfers retirement
  of its SDL world texture to the old SDL renderer owner. Shock.c recreates the
  presenter before submitting more frames and starts in Original; see section17.

Build5 simulated submit and compose failures were exercised; see section21.

16. CACHE / LIFETIME DESIGN

MacSrc/GpuTextureCache.c/.h owns tightly packed pixels, keyed by dimensions,
content hash and byte equality. Resource addresses are not identities. Temporary
monitor/model bitmaps, unlocked resources and RSD decode buffers cannot dangle
inside retained commands. Stride padding is excluded from identity.

Limits: 512 slots, 16 MiB CPU index pixels, maximum1024x1024 per bitmap.
A linked LRU evicts historical unpinned entries, avoiding frame-counter wrap.
Every current acquisition pins its stable slot. Prior pins are released only
after primary retained commands are invalidated at the next supported begin.
Paused/palette replay, picking/secondary views and GL reconstruction do not
release those pins. An over-budget pinned working set rejects the whole view.

CPU retirement only marks a slot. Native GL deletion is deferred until the
next guarded submission, before replacement upload. CPU allocation failure may
retire unpinned historical entries; existing commands remain valid. Resource
reset forgets or deletes native names appropriately while retaining CPU data.
On a replaced context, resources_dispose(lost=1) makes no GL calls and leaves
the SDL world target attached to its old SDL renderer's ownership list. The
presenter retires that complete owner before allocating a new presenter; owned
CPU texture pixels survive for an explicit later GPU retry. See section17.

The native command bounds remain4096 draws /32768 vertices, with safe rejection.
GPU index storage is additional to the CPU16-MiB bound; world RGBA/depth-stencil,
VBO, metadata, SDL/UI buffers, software backup and driver overhead are separate.
The cache is not a total process-memory budget.

Content is hashed on acquisition and compared after a matching hash; current
pixel content implicitly versions animated resources. No unsafe pointer shortcut
or guessed generation tag was introduced. Palette changes update a separate
1024-byte palette, not immutable index textures. Remaining hashing/software/UI
costs are recorded honestly rather than claiming a complete performance port.
