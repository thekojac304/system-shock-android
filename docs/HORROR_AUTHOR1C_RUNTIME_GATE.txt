2. DOOR EXTENT AND STATE
The explicit portal diagnostic now records ID, object and paired-half IDs,
connected inferred regions, exact object plane, terrain-edge plane, cardinal
heading axis, panel span, static aperture span in tile and world coordinates,
baseline frames/state, source and confidence. The one-tile collision panel
width comes from faceobj.c's fixed +/-0.5 local X half-width. Terrain aperture
width comes from the renderer face_obstruct table. Object pitch/bank and
heading axis must agree with a boundary; unverified doors fail closed.
Both Medical paired-door pairs link to real door objects. Frames 0,1,2 block;
frame >=3 may transmit only if every linked half has reached that threshold,
following doorparm.h and faceobj.c. This conservatively handles partial-open
animation without guessing the changing bitmap silhouette. It changes no
gameplay door code, save state, collision or serialized map.

58/63 Medical and 54/58 Executive doors have a validated collision-plane and
static terrain-aperture record. The remaining 5/4 interior or unsupported
doors remain unresolved. Actual render-bitmap panel width, transparent pixels
and opening direction/shape per animation frame are not certified. The
offline generator still treats every portal as closed, including baseline
doors whose frame is open; live-state light propagation was not implemented.
Thus the record is a useful conservative portal foundation, not a completed
live door-light solution.

3. SURFACE/FRAGMENT RECEIVER AUDIT
An offline audit now checks nine points on each flat floor/ceiling receiver
face for each generated light, using the existing edge-height ray test and
closed portal set. It reports full, partial and no visibility separately.
This tests the existing tile-mask assumption; it does not pretend that nine
samples prove every fragment or identify the renderer's emitted wall draw.

Medical light-to-flat-face pairs: floor full 754, partial 454, none 27;
ceiling full 692, partial 296, none 247. There are also 475 complex-tile
receiver/light pairs with unverified draw geometry. Executive: floor full
763, partial 332, none 17; ceiling full 682, partial 267, none 163; 280
complex-tile pairs. A focused synthetic case proves the failure: the center
of a receiver tile is visible while a corner of that same tile lies behind
an adjacent solid tile. Applying the current tile list to a whole draw would
light that hidden fragment. The accepted GPU renderer currently assigns
receivers at draw granularity from tile metadata; it has no generated stable
source-face ID or per-fragment portal test. No independent map mesh was made.

Because these failures are substantial, no runtime light-list compiler was
introduced. The needed bounded structure remains tile/face -> light list plus
stable emitted draw identity and conservative fragment-safe clipping or split
at a true visibility boundary. The existing four-light receiver budget stays.

Emissive masks and local-light casting remain separate. These textures can
still propose local lights under the pre-existing surface rules. Their whole

the housing glow. The new mask metadata has not been compiled into that shader.
Other mixed art remains non-emissive pending review.
