2. SURFACE ID CONTRACT AND GPU DRAW ATTACHMENT
GpuSurfaceId.h defines level, tile X/Y, terrain class, face/edge index,
subface, terrain type, own raw geometry key, optional neighbor raw geometry
key and valid bit. Floors and ceilings have distinct classes. External wall
edges and emitted strips have separate face/subface fields; internal wall
face indices cover diagonal and slope-generated internal faces. Own geometry
key packs original tile type, raw floor/ceiling heights, parameter and mirror
bits without a hash. External walls also bind to the adjacent tile geometry
key. Draw metadata separately records material resource ID. Identity never
uses GPU buffer index, pointer, traversal order or frame number. It changes
no saved format or gameplay state.

frterr.c now sets this context immediately before its original wall,
floor and ceiling emission, and tags both emitted floor/ceiling subfaces.
Single ceiling polygons use subface 0; only two-element ceilings use
subfaces 1 and 0, matching the offline flat-face record.
GpuWorld.c copies it into each captured terrain Draw. Object draws carry an
invalid ID; missing or out-of-range terrain identity also fails invalid.
The original terrain traversal and geometry remain authoritative. Unsupported
generated metadata must leave the accepted neutral GPU draw intact; no
generated-light application path was installed in this phase. The Android QA
native build compiles this path, but a live draw-by-draw ID census and map
mutation test were not performed. Thus the source contract is implemented,
while on-device completeness is still unverified.

3. RECEIVER APPLICATION AND PARTIAL FACES
scripts/horror_surface.py is a separate conservative offline compiler. It
reads a validated generated profile and emits sorted light ID -> exact flat
floor/ceiling SurfaceId pairs. It never upgrades the earlier tile mask to a
draw receiver. It proves a sufficient terrain-clear case: every cell in the
axis-aligned XY bounding prism from source to the entire target square must
be an ordinary flat tile, contain the full source-to-face vertical interval,
and contain no recorded door tile. Every source-to-face-fragment segment is
inside that prism, so no accepted face has a known hidden terrain fragment.
Other flat faces, all complex faces, wall faces and all partial cases receive
no generated light. This is deliberately over-restrictive and is not a
runtime receiver loader. Dynamic objects are outside this terrain proof.
The compiler records baseline/rules signatures but does not authenticate
them against live archive resources; no runtime fail-closed profile loader
or active light-list budget has been implemented.

4. ANIMATED DOOR APERTURE
The AUTHOR1C collision/static portal records remain 58/63 Medical and 54/58
Executive doors. Source inspection confirms frame 0 through 2 is closed for
physics/facelets and frame >=3 is open for that purpose. Game object rendering
uses a frame-specific cached bitmap, whose width/height set plane extents;
the door remains an object plane and paired halves have independent frames.
The existing portal_transmits policy requires both halves at frame >=3.
Neither that threshold nor the earlier Flight visual parity recording
certifies the luminous aperture silhouette of Medical/Executive door art
at each frame. No bitmap transparency/width sequence was decoded here.
The AUTHOR1D receiver compiler therefore treats every portal as closed,
including fully open frames. This prevents closed-door spill offline but
cannot provide conservative increasing/decreasing live spill. No portal
runtime record or lighting invalidation was added.

9. REMAINING ERRORS AND ESTIMATE
Potential false positives: generated source placement/color/energy remain
unreviewed visual inferences; the flat-prism terrain proof ignores occlusion
by dynamic objects; live ID correctness under terrain mutation is not yet
measured. It does not claim wall/complex receiver safety. False negatives:
the bounding prism rejects many clear narrow sight cones, all complex and
wall faces, every door crossing even when open, and 16/17 Medical held-out
tiles. Medical tiles 1370, 1438 and 1502 still lack proposed tile receivers.

engineering/visual review, very low confidence. This is not a measured
station-wide completion rate. Current runtime-safe held-out coverage is too
low to estimate finished visual authorship from these two levels.
