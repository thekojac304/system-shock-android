3. PARTIAL-FACE FAILURE TAXONOMY
AUTHOR1D's axis-aligned whole-face prism rejected clear narrow sight cones as
well as genuinely hidden face fragments. It also excluded all slopes, walls,
diagonals and entire door cells. This was safe but very wasteful.

Each new diagnostic relationship records SurfaceId, light ID, face type,
full/blocked/partial/unsupported permission, a nine-point visible sample
pattern, first blocking cell/edge and reason, traversed beam apertures,
face-local polygon(s), planar-boundary/safe-split status and portal references.
V/B/- mean visible/blocked/outside polygon; iteration is U outer, V inner.
Samples explain the geometry; they do NOT grant receiver permission.

These statuses describe the supported conservative model. In particular,
blocked by an excluded door cell is not proof that the actual rendered door
occludes the entire cell. Unsupported source/complex geometry is recorded
separately. Step-wall strips and exotic wall topology are not enumerated as
certified draws. They retain neutral rendering and are outside this census.

Some corner configurations require a union of two convex polygons. Convexifying
their union indiscriminately fills the hidden notch. An actual Medical T2097 /
source T2034 counterexample exposed six bad admitted probes during development.

with nearly tied X coordinates. That was fixed and the precise counterexample
is now a regression test. None of those failures survives in the final audit.

4. REPRESENTATION CHOSEN
Offline beam clipping through convex terrain cells, followed by face-local
convex polygon records. The source must lie strictly inside a supported volume.
Each shared aperture is clipped against both cells and the preceding beam.
The source/aperture cone and forward plane constrain subsequent cells. A straight
segment is monotone in each horizontal coordinate, preventing cyclic paths.
Convexity ensures the segment between entry and exit stays inside each cell.
The final intersection with the receiving face is the permitted region.

Supports ordinary flat floors/ceilings, simple slopes 6..9 with all four mirror
modes, diagonal tiles 2..5 and their internal wall, and ordinary external walls
against a fully closed neighboring edge. Raw solid-neighbor geometry keys come
from the signature-checked archive; they are not fabricated as zero.
Floor/ceiling IDs reuse AUTHOR1D. Wall face/subface IDs follow frterr.c's emitted
indices; supported full external walls use subface 0. Identity remains unrelated
to draw order, buffer offsets, camera or texture UV orientation.

Use map-local X/Y for floor/ceiling masks and horizontal-axis/Z for wall masks.
Store axes and origin with the diagnostic record. Full faces need no mask;
blocked/unsupported faces receive no generated light. Partial polygons shrink
inward by 0.00002 map units after union. No runtime ray tracing or shadow system.
This remains an offline diagnostic format, not a ready-to-load GLES profile.

5. BOUNDS AND RUNTIME COST MODEL
Hard limits: 4 polygons per light/SurfaceId, 8 vertices/planes per polygon,
4 local lights per draw. Thus at most 16 partial polygons / 128 half-plane
tests per draw's fragment, with early rejection. Actual maximum here is two
polygons per relationship, Medical 7 vertices and Executive 6. Full flags incur
only the existing radial-light calculation. Offline traversal is capped at
512 beam states and depth 12; state/polygon overflow disables the relationship
or source. Depth truncation omits further receivers. No unbounded runtime work.

Chosen future application: fragment test of interpolated face-local coordinates.
It requires zero extra draws, preserves the captured SurfaceId, and avoids
retessellating the existing clipped draw stream. Splitting draws would require
new triangle emission and additional draws for each light-mask combination.
The fragment option is simpler here. Highp interpolation, packed-plane precision,
seams and actual Android cost still need a runtime gate. Bounded is demonstrated;
cheap enough on the target device is NOT measured or certified.

6. DOOR ANIMATION GEOMETRY MODEL
Inspected gameobj.c, objsim.c/Headers/objsim.h, objuse.c, doorparm.h,
citres.c, resformat.c and the actual RSD decoder contract.
Door art resource = 2400 + class-local subtype index; current_frame selects
the resource subframe. The object center/orientation is fixed. Each frame's
bitmap width/height determines local half-extents w/128 and h/128 at the active
scale=0 path. UV (0,0) is the upper-left corner. Palette index zero is cut out
when BMF_TRANS is active. Frame zero with RENDER_BLOCK disables transparency.
The model always blocks generated crossing at frame zero, conservatively.
gameobj.c also snaps XY raw fractions 0xff00 to the next integer tile edge;
the old collision-plane location is not always the rendered-plane location.

Opening plays resource frames forwards; closing plays them backwards. There is
no continuous geometric translation between bitmap frames. Paired halves have
independent objects/frames, with use_door coordinating their animations. Medical
182/183 and 240/241 occupy adjacent half-panels, not the same centered panel.

Decoded all 24 door resources used by these two profiles: 124 frames, including
17 animated resources. No frame dimension changes occur in these sequences.
Blocking silhouette changes stepwise through transparent art. The Python RSD
reader follows the engine's literal/run/skip/long-op/pad behavior, with strict
bounds; synthetic command tests cover both short and long forms.

Candidate representation: largest all-transparent axis-aligned rectangle per
frame, inset by one texel. Every intersected texel was checked: 101854 checks,
zero opaque texels admitted. This validates local bitmap rectangles only.

7. DOOR GATE FAILURE / PORTAL LOGIC
The candidate is insufficient for coherent animated propagation. Twenty-one
consecutive-frame rectangle transitions lose some previously admitted area.
Resource 2404 frame 1->2 loses 100% overlap; 2408 loses 75% at 1->2; paired-half
resources 2431/2432 lose about 58.82% at 3->4. A largest rectangle can relocate
even when the intended aperture is growing. It would move light abruptly.
No invented frame>=3 threshold repairs this; that threshold is physics policy.

Furthermore, world-space projection through the snapped render plane, terrain
aperture intersection, and combined paired-half silhouettes are not certified
by this implementation. Local valid rectangles do not prove a valid cross-portal
receiver mask. The complete door gate therefore FAILS. The door CLI deliberately
returns a failure exit status after writing its evidence. This is not a PASS
based only on source inspection or transparent pixel counts.

Static receiver compilation retains AUTHOR1D's opaque door-cell fallback for
every state, including open. Portal references on nearby affected records are
conservative invalidation dependencies, NOT permission to cross. Reference tests
show missing/closed paired halves reject and a frame change invalidates only
dependent records. There is no engine callback or runtime receiver cache yet.
No opening/closing receiver variants are emitted, and no level rebuild per
frame is implemented. A future fix needs coherent bounded frame masks and their
actual world-space/paired projection before it can replace this fallback.

18. REMAINING UNSUPPORTED GEOMETRY / RISKS
Types 10..50, two-subface complex slopes, multi-strip external step walls,
special walls, nonzero-parameter nominally flat tiles, ambiguous doors and
all animated door crossing remain generated-light-disabled. Unsupported
sources and any over-budget case fail closed. Normal GPU geometry is untouched.
Occlusion by arbitrary movable objects is outside the terrain model; this is
not dynamic shadowing. Live terrain mutation along an intermediate beam must
invalidate affected receivers before any runtime loader is safe. Baseline
archive matching and receiver SurfaceId alone are insufficient for that event.
Live draw correspondence, packed floating-point precision and mask seams still
need validation. The offline floating-point audit does not certify GLES highp.

19. AUTOMATION ESTIMATE / COST-BENEFIT
After both offline results, retain roughly 50-60% automatic / 40-50% manual
ordinary-area setup, VERY LOW confidence. Do not increase it because the code
is reusable or because 11/17 tiles now have nonzero falloff. That ratio is not
a measured station-wide work percentage. No generated visual review exists.

Partial geometry is no longer a reason to abandon all automation: obvious
fixture inference plus compact terrain receivers works materially better.
Further broad inference engineering is not justified now. Completing automated
door propagation still needs a coherent frame representation, actual paired
projection, runtime state invalidation, packing/shader work and visual QA.

For production progress, favor a hybrid: generated obvious fixtures, explicit
level/hero-room overrides, per-level color grading and contrast curves, carefully
placed manual haze/fog and a limited set of hand-authored local lights. Manual
overrides still require safe receiver constraints; post-processing alone does
not solve wall leakage. The accepted GLES backend gives a useful foundation
for this lower-engineering-cost visual workflow. No such authoring is performed
in AUTHOR1E, and no full-station work is authorized by this report.
