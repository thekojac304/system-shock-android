2. FLICKER MISMATCH ROOT CAUSE
The original renderer updates transient scalar light per map tile. GPU GENERATED
used the generated fixture profile's static intensity and reviewed emissive mask
without consulting that live transient value. A nearby surface could therefore
dim while the fixture mask stayed bright. The source tile exposes the existing
me_templight_floor/ceil and permanent me_light_floor/ceil values.

3. FLICKER SYNCHRONIZATION IMPLEMENTATION / RESULT
At each generated frame, sample the original transient value at a generated
source's exact tile and choose floor or ceiling by source height. Only after two
observed transitions does the guarded multiplier become
clamp((15 - permanent + live) / 15, 0, 1). Static samples stay at 1.0.
The same multiplier scales generated RGB source intensity and a draw's reviewed
emissive output when source tile and material uniquely match. Object sources and
ambiguous matches are left alone. The device log observed Medical source 226 at
tile (28,24), material 35, live 0, permanent 13, multiplier 0.133, and a matching
emissive draw. Focused device tests passed stable, changing, and reset cases.
The code path and live association are verified. The short screenshot sequence
did not show a reliable before/after brightness change for the previously
reported visible lamp. Its exact temporal visual sync remains unconfirmed.

4. POST-PROCESS ARCHITECTURE
GPU GENERATED renders to its existing world target. The post pass copies that
world texture into a GLES3 texture, shades one fullscreen triangle into a second
SDL target, then composes that target before HUD, menu, and touch controls.
The source is sampled with texelFetch at native world resolution. ORIGINAL,
VIS1B HORROR, GPU PROOF, and GPU GENERATED remain selectable. Post runs only
for GPU GENERATED on Medical or Executive. Other levels resolve to neutral.
Missing shader/target, failed copy, or failed pass returns the ungraded world;
the ordinary GPU/software fallback remains downstream. These fallback branches
were inspected, but explicit fault injection was not run this phase.

5. COLOR / TONE CONTROLS
The centralized preset block includes exposure, power contrast, black toe,
highlight shoulder, saturation, shadow and highlight tint RGB and strengths,
vignette strength/radius/softness, and grain strength. The shader uses a bounded
power curve with a sqrt toe lift and shoulder compression. A first hard black
cutoff was rejected on hardware and replaced before the final build because it
hid near-black structure. No separate gamma control was needed for these six
presets; the game's existing gamma remains available.

6. VIGNETTE
World-only smooth radial falloff, controllable by preset strength, radius,
softness, and an independent On/Off menu switch. Medical A's 0.10 strength is
subtle on the phone and helps edge focus; it does not form a large dark oval.

7. GRAIN
World-only stable pixel-coordinate noise, independently switchable. Preset
strengths are 0.005-0.012. The stable pattern avoids temporal crawl and was
barely visible at ordinary phone viewing distance. It can remain enabled by
default, but is not a major visual contributor.

8. BLOOM
Skipped. The current pass has a composed world image but no clean emissive-only
source buffer. A global brightness threshold would bloom ordinary bright palette
textures and risk making walls look like lamps. Adding a selective mask buffer
and blur would be disproportionate for this phase. No bloom toggle is shown.
