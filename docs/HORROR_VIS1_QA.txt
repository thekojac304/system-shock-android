3. RUNTIME TOGGLE AND PRESERVATION

Pause -> Video -> VISUALS ORIGINAL / VISUALS ENHANCED -> Return.
The normal Video options pushbutton also accepts H while that panel is open.
It refreshes the world immediately behind the panel, then redraws the panel.
No level reload, renderer teardown, save/load, gamma change or camera move.
Preference: prefs.txt, world-visuals = original|enhanced. Default is Original;
missing/invalid values in existing preference files resolve to Original.
This preference is not added to Player or FullMap and is not serialized in saves.

Original is an explicit bypass. Terrain keeps its original scalar calculation,
objects call the unchanged original show_obj body, and the actual original shade
table remains bound. Original does not select a zero-intensity modified bank.
Banks are separate allocations; original SHADTABL and palette bytes are not edited.
Every Enhanced scope restores the prior light-table pointer, model CLUT pointer,
fill type, fill parameter and scalar state before returning. Object early returns
are inside the wrapper. Tile state is restored before objects are drawn.
Nested excluded camera/picking views temporarily restore baseline bindings and
then restore their parent scope. World state is restored before fr_send_view/UI.
No cosmetic value is assigned to permanent/transient map-light fields.
Gameplay detection continues reading the original map values.

Guarded Original paths: cyberspace, non-Medical, incompatible map, OpenGL,
infrared/nonzero CLUT, nonstandard light table, LSD/SIGHT, cutscene palette,
picking, secondary/HACKCAM, palette/solid/no-render view flags.
Turning Enhanced on during one of these conditions preserves the preference;
the effect resumes only in a supported normal world view.
One loading sequence can log an initial incompatible signature before the final
load_textures call validates the fully loaded map; this is fail-closed behavior.

4. LIGHTING, TABLES AND COVERED PATHS

Precedence in VIS1:
  Original level default -> empty common/inference stage -> named tile mask
  -> surface/material exceptions -> dynamic/special-view exclusions.
Selection belongs to each drawn tile/object, not the camera's current region.
The neutral landing separates the cool bay from the warm alcove. Different
banks can appear in the same frame; crossing a boundary does not change the
whole screen's profile. A moving object can still change bank at a tile boundary.

Scalar response uses 8.8 darkness (higher = darker):
  above row 8, compress excess darkness by 3/4;
  add 1.25 rows to ordinary floor/object samples, 4.5 to ceiling samples;
  subtract two stationary Manhattan tent pools;
  clamp authored floor/object darkness to 0..11 and ceiling to 0..12.
Pool records (x,y,radius,floor strength,ceiling strength), all in tile/row units:
  (30,24,3,4,3), (26.5,20.5,2,3,2).
These coordinates are within/along the inspected room, not invented map sites.
This response runs BEFORE existing transient light subtraction, lamp/muzzle
distance terms, global modifiers, and special rend3 full-bright behavior.
The caps constrain the authored component; original functional effects can still
alter the final result. Terrain interpolates scalar vertex values, not indices.
Dark ceilings and brighter bed/floor areas both remain; gamma is untouched.

Precomputed 16x256 indexed banks: Original=0, cool=1, warm=2 (12 KiB total).
Only palette-load initialization performs nearest-color searches. Per-pixel
rasterizers retain their existing shade-table lookup. The cool bank gently
reduces red and lifts cyan/blue. The warm bank targets restrained amber by
luminance; bright and saturated source colors receive smaller changes.
The original palette's strongly blue slate made a simple warm multiplier map
back to the same blue ramp. The final luminance-based target fixes that specific
quantization failure without a truecolor extension.
Actual owned-palette table differences: cool 302/4096, warm 1271/4096 entries.
These are table-entry counts, not percentages of screen pixels.

Protection:
  all shade row 0 entries copied unchanged (full-bright response);
  source indices 0..31, 255, and entries invariant across original shade rows;
  protected outputs preserved, ordinary colors never remapped INTO reserved ramps;
  transparency and palette-cycle indices retain original semantics;
  inspected luminous texture IDs 35 and 216 bypass BOTH scalar and color changes;
  floor family 37 retains neutral color while scalar treatment applies;
  displays and original unlit/light-type exemptions use Original.
These protect the intended original fixture colors, which include blue/purple
lights; VIS1 does not repaint those fixtures to white or amber.

Terrain: external/internal walls, floors and ceilings. External walls resolve
the actual selected texture (including neighbor texture selection).
Objects: bitmap/pickup sprites, anchored sprites, multiview critters, doors,
textured panels, polygon/model CLUT rendering, and cube paths receive a scoped
bank at the object's location; ordinary object darkness uses the same response.
Model CLUT and bitmap/terrain ltab are bound together. Dynamic monitors are exempt.
Object source code is covered; hardware images verified doors, supplies and
control/display behavior, not every possible representation or enemy species.

Explicit unsupported color paths: translucent FAUBJ_TL_POLY, voxels, and invisible
critters use their original color/scalar path. Their blends are not rebuilt.
No such translucent object was identified in this starting mask. This is a known
integration limit, not claimed comprehensive translucent visual coverage.
Special procedural world effects may use raw colors instead of CLUTs; those
colors remain original. No fullscreen palette processing is used.

9. VIS2 / AUTO-AUTHORING REUSE AND RECOMMENDATION

Keep the indexed approach for the next bounded iteration, pending user visual
acceptance. Scalar distribution produced the strongest change; material banks
can provide localized warm/cold contrast without changing gamma or HUD. There is
no evidence here requiring a truecolor renderer extension. Do not expand across
Medical until the pending enemy, functional-light and special-transition checks
pass and the warm ramp/banding are judged acceptable on the device.

Reusable now: one persistent Original/Enhanced architecture; engine-independent
tile/material/pool data; resolved texture-ID exceptions; original-table-based
bank generator; scoped terrain/object/CLUT binding; fail-closed map validation;
special-view priority; fixed camera A/B workflow and opt-in timing.
The static C records are a first data source, not a requirement to write renderer
code for every room. A later external/generated data provider can populate a
level default, common/inferred rules, named masks and pool records, then apply
surface exceptions and dynamic overrides through the same binding scopes.
No external loader, whole-level profiles or inference engine is claimed in VIS1.

Useful generator inputs already available: original floor/ceiling darkness,
resolved texture IDs/families, luminous-texture exceptions, fixture/display and
pickup locations, floor/ceiling geometry, doors and adjacency. Future providers
can add hazard flags, trigger/quest state and music zones as weak hints. Dynamic
state belongs at the last precedence stage and must never rewrite gameplay
lighting. A generator should emit first-pass records for review, with named
overrides only where art direction needs them; manual authoring of every room
from scratch is not the intended architecture.
