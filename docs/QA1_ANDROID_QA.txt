QA1 - Android touch QA tools
Validated 2026-10-02. No commit or push.

1. TOUCH ACCESS
Enter a live game, tap the existing SET overlay button, then QA TOOLS.
This uses existing touch settings space rather than adding an overlapping
gameplay control. God Mode, Full Health / Energy, all destinations, and Close
are large touch buttons. Opening the panel cancels held gameplay controls;
the modal owns touch input until closed. The world continues simulating.
Closing restores the existing input mode and control layout.

2. VISIBILITY AND BUILD ISOLATION
The qa Gradle variant enables RP5NP_QA_TOOLS. CMake defaults it OFF.
The preference qa_cheats = true is also required; its default is false.
Normal builds exclude the command implementation and guarded engine hooks.
The existing touch UI renderer contains dormant QA panel definitions, but
normal builds cannot enable or execute QA tools.

To opt in on a device: launch the QA app once, save and stop it, then run:
  ./scripts/set-qa-cheats.ps1 -Enabled $true
Use -Enabled $false to disable, and -Serial when multiple devices are attached.
The helper targets only io.github.raposomiguel50.systemshock.qa, backs up prefs,
preserves other preferences, refuses to interrupt a running app, and verifies
the write. Relaunch, enter a game, then SET > QA TOOLS.

3. GOD MODE
An early return in damage_player suppresses normal player damage while both
the QA preference and in-memory God flag are enabled. Enemies and simulation
remain active. The menu explicitly displays ON/OFF. State survives opening
and closing the menu, and resets on new game, load game, and process restart.
It is not stored in savegames. Contamination can still accumulate; disabling
God while contaminated can rapidly kill the player. Scripted outcomes that
do not use damage_player are not guaranteed to be prevented.

4. HEALTH AND ENERGY
Sets current hit_points to PLAYER_MAX_HP and energy to MAX_ENERGY, then marks
vitals for redraw. Does not modify maxima, inventory, or contamination.
Hardware logging confirmed hp=255 and energy=255 after the action.

5. TELEPORT IMPLEMENTATION
Touch commands are queued and handled after uiPoll unwinds. Before transition,
the destination's map metadata and tiles are read from CurrentGame.dat and
validated. Failure leaves the current deck unchanged. Successful requests
clear physics controls and call trap_teleport_func, the existing transition
path through go_to_different_level. This saves the old deck, loads the target,
restores inventory/art/physics, runs level-entry triggers, and moves the player
through obj_move_to. No separate music path or direct level-global rewrite.
Selecting the current deck is a no-op. The transition closes the QA panel.

6. SAFE SPAWNS
Spawns are selected from the actual saved destination geometry, not assumed
fixed coordinates. Only open tiles without object references, with standing
headroom and a same-height open cardinal exit qualify. Radiation/biohazard
tiles are excluded except Beta Grove, which requires God Mode ON. Prefer the
most available exits, then proximity to map center. Z uses floor height plus
the engine's standing pelvis offset. The archive must be a supported 64x64
non-cyber map with validated fixed resource sizes and zshift 0..5.

12. KNOWN LIMITATIONS
The panel captures touches but does not pause hazards/enemies. Enable God for
hazardous testing. Beta requires God; accumulated contamination is not cleared
by heal or by toggling God. Teleport does not unlock story progression. Spawn
preflight rejects unsupported resources, but cannot guarantee all later
script changes or every modified save. God is a damage guard, not a bypass of
every scripted death. QA tools are for live, non-cyber gameplay. Existing
overlay suppression rules, including controller behavior, remain in force.
