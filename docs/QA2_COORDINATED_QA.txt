B -- MENU TAP RELIABILITY
Root cause: setup assigns the title menu root to _current_view. The touch
target query classified parts of it as WORLD, generating two press/release
pairs. Legacy UI buffering turned them into LDOUBLE, ignored by title handlers
which accept LDOWN. Ordinary control taps also entered that double-click delay
and could be delayed/coalesced across rapid taps.

Before: completed control tap -> ordinary down/up mouse queue -> double-click
buffer; misclassified title taps -> two pairs -> LDOUBLE.
After: completed UI control/NONE tap -> one source-aware marked down/up pair,
immediately dispatched in order without double-click buffering. TAP metadata
is stripped before callbacks. World/object tap double-clicks retain their
existing path. Physical mouse/controller click history and aggregate button
ownership remain intact; keyboard behavior is unchanged.

Drags: movement beyond existing slop starts marked native drag edges.
Title/wrapper buttons and list actions ignore drag-down activation, while
sliders keep down/move/up. Shift is explicitly masked in all relevant game
consumers. Cancel/background cleanup retains release provenance and never
releases an overlapping physical/controller hold.

Timing: stationary ordinary-menu taps permit up to 1000 ms; gameplay cursor
and movie thresholds remain 350 ms. Slop, anchoring and gameplay sensitivity
are unchanged. Raw input timestamp domains were not redesigned.

Automated PASS: real SDL adapter + real uiPoll/region dispatch tests cover same-frame
single/rapid taps, one activation per tap, native mouse double-click buffering,
cancellation releases, marked drags and overlapping physical holds. All prior
touch suites pass. Visual QA and full ARM64 builds pass.
Hardware PASS: ordinary menu selections respond to a normal single tap without
spam-tapping; no obvious regressions were observed. Per-menu enumeration,
slow-tap limits, drag/slider and physical-input checks were not individually
reported and remain pending rather than inferred from this broad acceptance.

Files: touch_controls.c, bridge APIs/implementation, INPUT mouse.h and
sdl_events.c/.h, UI event.c, GameSrc input.c classifier, setup.c, wrapper.c,
mfdgames.c and focused touch tests.

C -- RELOAD / AMMO RADIAL
Control: a new editable AMMO touch button near the existing top-row wheels.
The baseline had no dedicated reload touch control. Existing keyboard and
controller ammo-cycle actions remain unchanged.

Short tap: native reload_weapon_hotkey(..., data=0), reload current ammo with
native fallback. This also reloads single-ammo weapons correctly. The stock
controller data=1 ammo-cycle behavior remains on its existing control.
Hold: 320 ms, the same shared wheel threshold. No action occurs on opening.
Release on a valid sector invokes exactly one native reload or ammo selection;
center/outside/disabled-sector release cancels. Rapid taps remain single actions.

Population: equipped weapon only, RELOAD plus compatible ammo with reserve or
loaded rounds. Current ammo is marked even when only its magazine remains.
Counts show loaded + reserve rounds; unavailable alternates are hidden initially
and disabled by live refresh if depleted while held. IDs bind both weapon slot
and gun definition; stale/replaced weapon choices are rejected on release.

Specific ammo: native unload_current_weapon then change_ammo_type, matching the
weapon MFD. Quantities, clips, heat, energy settings and balance stay owned by
native routines. Byte-counter overflow on returning a magazine is rejected
before mutation. Empty/invalid slots are rejected. Beam and hand-to-hand
weapons have no ammo choices. Beam-projectile weapons retain their native
setting/heat semantics; a setting value is never interpreted as an ammo ID.

Context: works in LOOK and gameplay CURSOR. A held cursor/attack gesture
prevents acquisition. Mode/UI/controller/lifecycle interruptions cancel;
other wheels retain their context rules. Existing settings/control IDs and
keys are preserved; old v3 settings gain the default new button placement.
The layout editor can move and resize AMMO.

Automated PASS: focused tap/hold boundary and timestamp-wrap tests, short taps,
reload/alternate/cancel, one/multiple ammo types, empty magazine, absent or
depleted alternate, stale slot/gun, LOOK/CURSOR and interruptions all pass.
Tests execute unchanged production native reload/ammo routines and prove
total-round conservation plus overflow rejection. Renderer/editor/settings
tests pass, and LOOK/CURSOR previews were visually reviewed.
Hardware PASS: AMMO short tap, hold opening, selection and cancel work and
the feature is usable through touch. Exact timing, individual ammo/weapon
edge cases, LOOK/CURSOR matrix and interruption checks were not reported.

Files: controls/settings/editor/render/radial header, bridge, GameSrc input.c
native adapter, INPUT touch action dispatch and focused tests.

gas, concussion, land mine, nitro, earth shaker) and seven patch types
(stamina, sight, LSD, medi, ninja, genius, detox). Internal object-explosion
grenades are excluded by the native player count. Health and energy become
255, their existing maxima; maximum stats are never increased.
No access cards, key/quest items, hardware, software or progression flags.

Mechanism: obj_create_base -> inventory_add_object -> native weapon pickup.
World-object autodeletion is temporarily disabled during each allocation and
restored immediately. Successful pickup destroys its temporary object through
the native inventory code. Failed admission destroys only the newly allocated
object. Full slots are checked before allocating. Duplicate owned candidates
are skipped. Byte counters use bounded top-ups, not addition.
Logs list successful gun triples and a concise summary. Object-limit failures
are reported as a partial loadout. No save routine is called and unrelated
save slots are untouched; an explicit normal save records the active loadout.

Automated PASS: tests cover empty and partially occupied inventories, seven-slot

workflow tests and rendered button review pass.
